Entity summary

By default id and *_id fields are BIGINT (PK/FK); codes, names, types, statuses and descriptions are TEXT; measurements NUMERIC(24,10); metadata JSONB; dates TIMESTAMPTZ. element_id is PK and FK of specialized property tables. Year fields are SMALLINT and positions INTEGER. Exact details are provided in the dictionary below.

Identity, classification and scope

erDiagram
    BUILDINGS ||--o{ BUILDING_CLASSIFICATIONS : classified
    BUILDING_MODELS ||--o{ BUILDING_MEASUREMENTS : measured
    ELEMENTS ||--o{ ELEMENT_CLASSIFICATIONS : classified
    CLASSIFICATION_NODES ||--o{ BUILDING_CLASSIFICATIONS : assigns
    CLASSIFICATION_NODES ||--o{ ELEMENT_CLASSIFICATIONS : assigns
    ELEMENTS ||--o{ ELEMENT_RELATIONSHIPS : origin
    ELEMENTS ||--o{ ELEMENT_RELATIONSHIPS : destination
    BUILDING_MODELS ||--o{ PART_MEASUREMENTS : scope
  • Block and building codes are unique within their parent territorial entity. Models are identified by building, code and version. A successor belongs to the same model series.
  • An element’s level and identifier scope must correspond to its model. Namespaces can be added within that model; mappings between different representations are expressed through explicit relationships between elements. Identity is not inferred from similar names.
  • element_kind distinguishes window, opaque and future types. Property tables have a discriminator protected by a composite FK; a specialized row is not mandatory if attributes are missing.
  • Review statuses are draft, reviewed, retired; measurement quality status is independent (unknown, reported, measured, estimated, derived, reviewed). An unknown measurement remains NULL, without a default value.
  • Part positions start at 1 and are unique among siblings, including root parts. Order does not by itself imply exterior/interior orientation. Hierarchies and successions prohibit self-references; revision 0006_integrity also checks longer cycles of parts and models.
  • assignment_type distinguishes reported and reviewed classifications. Classification domain, canonical units and selection of current measurements and assignments require validation in future services. Versions are not yet immutable by SQL constraint.
  • Relationships can represent equivalences between models; physical relationships, e.g. opening-wall, will require scope and semantic checks. Part measurements aggregated by model may exist before elements are assigned to the assembly.

Synthetic assembly example

A fictitious façade can have an assembly with several ordered parts, reused by several elements. Thickness belongs to each part; area belongs to element measurements or an aggregate source measurement. The interpreted material will be assigned in the methodological context, not in this table. For windows, frame, glass and air cavity may be represented as parts with different methods.

Import criteria

The HULC adapter distinguishes windows from opaque enclosures according to the original structure, retaining identifier, type, orientation, properties and source row. The component code will be an external classification, not the technical table type. Reported areas are stored as reported_area until it is known whether they are gross or net. A construction name is not a global identity. Layers are imported even without a material mapping. Source subtotals serve to cross-check quantities and are not added to disaggregated results. Zeros derived from missing inputs are not interpreted as confirmed absence.

A future geometric representation may reference elements through model and namespace IDs. Automatic HULC–IFC correspondence or ID stability across exports is not assumed.

Revision 0005_results adds supporting unique keys to element_constructions (id, element_id, construction_version_id) and building_measurements (id, building_model_id) for composite FKs in results.

0006_integrity checks classification domains for buildings (building_typology) and elements (component), and requires nonempty type and unit in all measurements. Dimensional compatibility remains pending. See integrity.

0007_resolution adds supporting uniqueness (id, part_id, building_model_id) in part_measurements, to reference aggregated measurements from results without inventing elements.

Revision 0008_reproducibility adds uniqueness (id, element_id) to element_measurements to reference an effective measurement from an individual contribution. Measurements selected in manifests are protected against ordinary changes; alternatives are recorded as new rows.

Categorized inventory adapter

flowchart LR
    A[Categorized workbook] --> B[Original records]
    A --> C[Versioned physical model]
    C --> D[Elements and measurements]
    C --> E[Assemblies and parts]
    B --> D
    B --> E

Original category codes are retained in elements.metadata.source_category, without assuming equivalence to catalog classification systems. Only opaque constructions with an exact normalized name match are linked directly. Windows retain their properties without automatic assignment of assemblies or frame or glass geometries. Parts are recorded as source_part until their function is interpreted. Levels, building reference areas and containment relationships are not inferred.

Aggregated measurements for each part remain separate from individual areas. Cached formula volumes with missing inputs are recorded as unknown (NULL); original values remain in sources.source_records. Do not add aggregate measurements and individual quantities without resolving overlaps. A cached volume does not necessarily equal solid material volume. The import report identifies constructions without a physical name match and formulas with missing inputs.

The importer resolves opaque construction names without a direct match through explicit equivalences confirmed by the operator. The association is stored in element_constructions; the original name remains in opaque_properties.construction_name and the source record. Normalized configuration is retained in sources.imports.configuration and forms part of snapshot identity when it contains equivalences. Building identity is not changed and direct matches are not overridden. Windows and part-to-material mappings are outside this operation. See HULC inventory import.

Batch writing and traceability

The importer groups source records, construction versions and parts, elements, measurements, subtypes and associations according to their dependencies. Existing assembly keys and latest versions are queried in groups. Entities generating identifiers request RETURNING with explicit parameter-order correlation; correspondence is not inferred from sequence continuity. Dependent relationships are written after retrieving the corresponding identifiers.

Constraints, triggers and the transactional advisory lock are retained. Unknown data, original names, physical fingerprint and scientific configuration do not change with a different batch size. The entire load is committed together. Simulation still writes no records.

Each label table uses the same structure. Its composite primary key prevents more than one label per entity and language. The foreign key restricts deletion of the original entity. source_text preserves the translated original; if it no longer matches the entity, presentation queries return NULL and the viewer retains the original. origin records editorial provenance; note can record ambiguity and limitations. These are neither scientific calculation inputs nor material equivalences. The loader does not overwrite differing labels; later revisions must be resolved explicitly.

Extended editorial labels

Revision 0012_extended_labels adds inventory.element_labels, inventory.level_labels and methodology.decomposition_node_labels. The first two reference the entity ID; the third uses the composite key (part_mapping_id, path). All three support ES/EN/FR, retain original text, provenance, note and creation date, and reject missing references. Scientific revisions and identifiers are unchanged. Downgrade is refused if the new tables contain labels.

Element names matching external identifiers and level names matching their code are not translated. The audit distinguishes these cases and empty names using not_applicable. Nodes retain reviewed ES/EN labels as fallback; current editorial labels take precedence in presentation, and French falls back to Spanish when absent.
