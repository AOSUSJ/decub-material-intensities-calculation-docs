Revision 0004_methodology implements ten tables. Physical description remains in inventory; properties and materials remain in catalog. Executable scientific methods and profile importers are not yet available.

Data dictionary

All id identifiers are BIGINT identity and primary keys. Foreign keys use restricted deletion. JSONB objects contain structured parameters, not executable code.

Additional constraints:

  • length(btrim(code)) > 0.
  • length(btrim(name)) > 0.

Interpretation and validation

flowchart LR
    A[Physical part] --> B[Versioned mapping]
    B --> C[Material A]
    B --> D[Material B]
    P[Versioned profile] --> B
    P --> E[Versioned method]
    E --> F[Future quantification]
    C --> F
    D --> F

Version statuses are draft, reviewed and retired. Interpretations distinguish pending, mapped and excluded. A pending interpretation may exist without method or materials. A mapped interpretation requires a method; sufficient assignments will be verified in the validation service. Exclusion requires justification; it does not imply zero quantity.

Fractions may be volumetric (volume), mass-based (mass) or area-based (area). A fraction may be unknown (NULL); a reported value requires an explicit basis. Other methods can use their own parameters without a fraction. The current model supports one assignment per material and interpreted part: contributions of the same material will be consolidated or modeled through distinct parts. A universal fraction sum of one must not be imposed: it depends on the method, voids and scope.

A profile may be in draft without a selected mapping set. The configuration_hash fingerprint has hexadecimal SHA-256 format; computing and verifying the fingerprint, canonical serialization and retaining effective inputs remain pending. The fingerprint alone is insufficient to reproduce a run. Future services will validate role and method compatibility, parameters, assignments, sources, completeness and statuses, as well as immutability of used versions. The database does not yet perform these cross-row checks or execute algorithms.

Revision 0005_results adds supporting unique keys to part_mappings (id, mapping_version_id, construction_part_id) and material_assignments (id, part_mapping_id, material_id) for composite FKs in results.

0006_integrity prevents changing the mapping selection of a profile that already has runs. When a profile fixes a versioned mapping set, the run must respect it. See integrity. Immutability of other parameters and dependencies is not yet guaranteed.

The single-material review service loads new sets/versions, per-part decisions and individual assignments without fractions. Version notes contain the reviewer and input/review fingerprints, and name-to-code resolutions when names are submitted. The service validates this subset of decisions; it does not replace future constraints for composite methods or select profiles.

Interpretation trees (0010_decomposition)

The methodology.decomposition_nodes table belongs to a versioned mapping. Derived data is not inserted into the original physical inventory.

erDiagram
    DECOMPOSITION_NODES ||--o{ DECOMPOSITION_NODE_LABELS : labels
    PART_MAPPINGS ||--o{ DECOMPOSITION_NODES : contains
    DECOMPOSITION_NODES o|--o{ DECOMPOSITION_NODES : parent
    MATERIAL_ASSIGNMENTS o|--o{ DECOMPOSITION_NODES : identifies
Field Type NULL Meaning
part_mapping_id BIGINT No Composite PK; FK part_mappings.id
path TEXT No Composite PK; ordinal path, e.g. 1.2
parent_path TEXT Yes Composite FK to the parent in the same mapping
kind TEXT No group, material, void, unknown
label_es TEXT No Spanish editorial label
label_en TEXT No English editorial label
justification TEXT No Explicit evidence, assumption or uncertainty
material_assignment_id BIGINT Yes Composite FK to the assignment of that part
material_id BIGINT Yes Material identity included in the composite FK

Positive dot-separated paths and the immediate-prefix relationship prevent cycles; FKs restrict deletion and scope. Only material admits the assignment/material pair (both required). Labels and justification are nonempty. The review service validates nonempty groups, childless leaves, absence of direct parent assignment and size/depth limits. These latter rules are not guaranteed against arbitrary SQL edits. Fractions and results are not recorded in this qualitative tree; repeated assignments by material are reused and do not constitute quantities.

Extended editorial labels

Revision 0012_extended_labels adds inventory.element_labels, inventory.level_labels and methodology.decomposition_node_labels. The first two reference the entity ID; the third uses the composite key (part_mapping_id, path). All three support ES/EN/FR, retain original text, provenance, note and creation date, and reject missing references. Scientific revisions and identifiers are unchanged. Downgrade is refused if the new tables contain labels.

Element names matching external identifiers and level names matching their code are not translated. The audit distinguishes these cases and empty names using not_applicable. Nodes retain reviewed ES/EN labels as fallback; current editorial labels take precedence in presentation, and French falls back to Spanish when absent.
