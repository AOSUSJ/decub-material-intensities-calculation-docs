Hierarchical decomposition

Status: qualitative hierarchical identification is available; quantities are pending.

Revision 0010_decomposition supports interpreting a terminal physical part through a versioned component tree. inventory.construction_parts is unchanged. Format 1 remains supported; format 2 adds components to every entry (null for individual decisions). To migrate an existing proposal, preserve metadata and fingerprints, change format to 2 and add components: null to each part before editing decompositions.

decub mapping propose --model-id 1 --hierarchical --file data/mapping/review_tree.json

A decomposed entry uses status: "decomposed", material_code: null, a justification and a list of at least two components. Each node has kind, label_es, label_en, justification, material_code and children. Groups require children; leaves cannot have children. Only material leaves accept an unambiguous catalog code or name. Synthetic component example (codes must exist in the review catalog):

[
  {"kind":"material","label_es":"Componente A","label_en":"Component A","justification":"Synthetic evidence","material_code":"synthetic_a","children":[]},
  {"kind":"unknown","label_es":"Componente pendiente","label_en":"Unresolved component","justification":"Synthetic uncertainty","material_code":null,"children":[]}
]
Kind Interpretation
group Intermediate grouping without its own assignment.
material Reviewed identification of a leaf.
void Non-material void in the chosen scope; requires justification.
unknown Unresolved component or interpretation; not zero.

The CLI validates scope, original metadata, fingerprint, languages, unambiguous names, justifications and structure (maximum 32 levels and 1,000 nodes per part). A physical parent or retired version cannot be decomposed. A decomposed part remains pending if it contains unknown leaves and becomes mapped otherwise; this does not certify physical completeness, fractions or masses. Simulation returns decomposed, decomposition_nodes and resolved_components (by part and path). Apply using the same review command, only after approval. A catalog assignment is reused if the same material appears in multiple leaves; the tree retains each location. Groups are not additional material contributions.

No child fractions or thicknesses are inferred. The future engine must select a non-overlapping resolution, quantify terminal contributions only, document voids and unknowns, validate conservation of quantities, and seal the effective tree and parameters. Result integration, reuse across models and quantitative estimates remain pending.

See composite products for interpreting trees.

The graphical viewer details represent reviewed trees using illustrative templates. They do not introduce subcomponent measurements or change the inventory.

Editorial localization of each node is stored separately through 0012_extended_labels; see the relational model. It does not change the scientific review format or content.
