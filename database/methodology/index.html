La revisión 0004_methodology implementa diez tablas. La descripción física permanece en inventory; las propiedades y materiales permanecen en catalog. No hay aún métodos científicos ejecutables ni importadores de perfiles.

Interpretación y validación

flowchart LR
    A[Parte física] --> B[Correspondencia versionada]
    B --> C[Material A]
    B --> D[Material B]
    P[Perfil versionado] --> B
    P --> E[Método versionado]
    E --> F[Cuantificación futura]
    C --> F
    D --> F

Los estados de las versiones son draft, reviewed y retired. Las interpretaciones distinguen pending, mapped y excluded. Una interpretación pendiente puede existir sin método ni materiales. Una interpretación mapped requiere método; que tenga asignaciones suficientes se verificará en el servicio de validación. La exclusión exige justificación; no equivale a cantidad cero.

Las fracciones pueden ser volumétricas (volume), másicas (mass) o superficiales (area). La fracción puede ser desconocida (NULL); un valor informado exige base explícita. Otros métodos pueden utilizar parámetros propios sin fracción. El modelo actual admite una asignación por material y parte interpretada: contribuciones del mismo material se consolidarán o se modelarán mediante partes diferenciadas. No debe imponerse una suma universal de fracciones igual a uno: depende del método, de los huecos y del alcance.

El perfil puede estar en borrador sin conjunto de correspondencias seleccionado. La huella configuration_hash tiene formato SHA-256 hexadecimal; el cálculo y verificación de la huella, la serialización canónica y la conservación de las entradas efectivas quedan pendientes. No basta con esa huella para reproducir una ejecución. Los servicios futuros validarán compatibilidad de roles y métodos, parámetros, asignaciones, fuentes, completitud y estados, así como inmutabilidad de versiones utilizadas. La base de datos no realiza todavía estas comprobaciones entre filas ni ejecuta los algoritmos.

La revisión 0005_results añade claves únicas de soporte a part_mappings (id, mapping_version_id, construction_part_id) y material_assignments (id, part_mapping_id, material_id) para las FK compuestas de resultados.

0006_integrity impide cambiar la selección de correspondencias de un perfil que ya tiene ejecuciones. Cuando el perfil fija un conjunto versionado, la ejecución debe respetarlo. Véase integridad. La inmutabilidad de otros parámetros y dependencias aún no está garantizada.

El servicio de revisión individual carga conjuntos/versiones nuevos, decisiones por parte y asignaciones individuales sin fracciones. Las notas de versión contienen el revisor y las huellas de entradas y revisión, y las resoluciones de nombres a códigos cuando se introducen denominaciones. El servicio valida coherencia de este subconjunto de decisiones; no sustituye las restricciones futuras para métodos compuestos ni selecciona perfiles.

Árboles de interpretación (0010_decomposition)

La tabla methodology.decomposition_nodes pertenece a una correspondencia versionada. No incorpora datos derivados al inventario físico original.

erDiagram
    DECOMPOSITION_NODES ||--o{ DECOMPOSITION_NODE_LABELS : labels
    PART_MAPPINGS ||--o{ DECOMPOSITION_NODES : contiene
    DECOMPOSITION_NODES o|--o{ DECOMPOSITION_NODES : padre
    MATERIAL_ASSIGNMENTS o|--o{ DECOMPOSITION_NODES : identifica
Campo Tipo NULL Significado
part_mapping_id BIGINT No PK compuesta; FK part_mappings.id
path TEXT No PK compuesta; ruta ordinal, p. ej. 1.2
parent_path TEXT Sí FK compuesta al padre dentro de la misma correspondencia
kind TEXT No group, material, void, unknown
label_es TEXT No Denominación editorial española
label_en TEXT No Denominación editorial inglesa
justification TEXT No Evidencia, hipótesis o incertidumbre explícita
material_assignment_id BIGINT Sí FK compuesta a la asignación de esa parte
material_id BIGINT Sí Identidad material incluida en la FK compuesta

Las rutas positivas separadas por puntos y la relación con un prefijo inmediato impiden ciclos; las FK restringen el borrado y el ámbito. Solo material admite la pareja asignación/material (ambos obligatorios). Etiquetas y justificación no vacías. El servicio de revisión valida grupos no vacíos, hojas sin hijos, ausencia de asignación directa del padre y límites de tamaño/profundidad. Estas últimas reglas no están garantizadas frente a modificaciones SQL arbitrarias. No se registran fracciones ni resultados en este árbol cualitativo; las asignaciones repetidas por material se reutilizan y no constituyen cantidades.

Etiquetas editoriales ampliadas

La revisión 0012_extended_labels añade inventory.element_labels, inventory.level_labels y methodology.decomposition_node_labels. Las primeras dos referencian el ID de la entidad; la tercera usa la clave compuesta (part_mapping_id, path). Las tres admiten ES/EN/FR, conservan texto original, procedencia, nota y fecha y rechazan referencias inexistentes. No se modifican revisiones científicas ni identificadores. La reversión se rechaza si existen etiquetas en las nuevas tablas.

Los nombres de elementos que coinciden con identificadores externos y los nombres de niveles iguales a su código no se traducen. La auditoría distingue estos casos y los nombres vacíos mediante not_applicable. Los nodos conservan las etiquetas revisadas ES/EN como retorno; las traducciones editoriales vigentes tienen prioridad en la presentación y el francés retorna al español si falta.
