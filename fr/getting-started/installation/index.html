Installation et configuration

Prérequis : Git, Python 3.11–3.13 (de préférence 3.12) et accès autorisé à PostgreSQL pour appliquer les migrations. La documentation et le SQL hors ligne ne nécessitent aucun serveur. Les versions PostgreSQL ciblées sont 14 et 16, vérifiées via une matrice CI ; vérifier que les deux tâches ont réussi pour la révision à déployer. Les autres versions nécessitent une validation supplémentaire.

python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev,docs]"

Linux/macOS : source .venv/bin/activate. Exécuter depuis la racine du dépôt.

Connexion

Copier .env.example vers .env et configurer DECUB_DATABASE_URL avec le pilote postgresql+psycopg. Utiliser les options TLS spécifiées par l'administrateur ; encoder les caractères réservés du nom d'utilisateur et du mot de passe. Ne pas inclure de secrets dans les arguments du terminal, YAML, la documentation ou les commits. Le rôle de migration nécessite l'autorisation de créer des schémas et tables dans la base autorisée. Utiliser un rôle à accès limité pour les opérations courantes lorsqu'il est disponible.

Gestion des révisions

decub db history
decub db migrate --sql
decub db status

--sql génère le DDL à partir d'une base vide sans connexion. status interroge la révision. Avant application, confirmer avec l'administrateur la base cible, les autorisations, l'absence de collisions de noms de schémas et la sauvegarde. Alembic utilise la table decub_alembic_version dans le schéma par défaut ; vérifier qu'elle n'appartient pas à une autre application.

decub db migrate --apply

Opération administrative

Cette commande modifie PostgreSQL. Exécuter uniquement sur une base autorisée et après examen du SQL. Ne pas effectuer de rétrogradation en production sans procédure de récupération approuvée.

Documentation et vérifications

python tools/build_docs.py
python -m http.server 8080 --bind 127.0.0.1 --directory site
python -m pytest

Zensical génère le site trilingue à partir de Markdown avec docs/zensical.es.toml, docs/zensical.en.toml et docs/zensical.fr.toml. L'aperçu combiné se trouve à http://127.0.0.1:8080/, avec l'anglais sous /en/ et le français sous /fr/. Pour un autre port, ajuster --site-url lors de la compilation et le port du serveur HTTP. Voir développement. Le serveur local permet de consulter la documentation sans publier d'informations. Les tests hors ligne ne remplacent pas la validation sur une instance PostgreSQL isolée.

Vérifier la cible PostgreSQL

Avant d'appliquer les migrations, configurer la connexion locale et exécuter decub db inspect. La commande utilise une transaction en lecture seule et renvoie la cible, l'utilisateur, la version, search_path, les privilèges de base, les objets existants et les tables de révision détectées. Elle ne crée aucun schéma et ne modifie aucune donnée. Réviser l'autorisation et les collisions possibles avec d'autres projets ; ce n'est pas une garantie automatique des permissions DDL ou de compatibilité structurelle. Sa sortie contient des informations d'infrastructure : ne pas publier sans révision.

Exportation des rapports Markdown en PDF

Facultativement, ouvrir la racine du dépôt dans Visual Studio Code et installer l'extension Markdown PDF (yzane.markdown-pdf). La configuration partagée .vscode/settings.json utilise .vscode/markdown-pdf.css pour les rapports A4, tableaux paginés, figures et numéros de page. Exécuter Markdown PDF: Export (pdf) dans la palette de commandes avec le fichier Markdown actif. Le PDF est enregistré à côté du fichier Markdown, y compris dans les sous-répertoires ; conserver les images relatives avec la source. Ouvrir le dépôt comme dossier racine, pas seulement le dossier du rapport. Préserver les préférences VS Code locales existantes lors de l'intégration.

Pour un saut de page explicite, utiliser <div class="page"></div> dans Markdown. Les tableaux préservent les mots entiers dans la mesure du possible ; ceux ayant jusqu'à quatre lignes de données sont gardés ensemble si possible, tandis que les tableaux plus longs peuvent se poursuivre avec des en-têtes répétés. La feuille de style tente d'éviter une dernière ligne isolée et ajuste les espacements sans réduire la taille des caractères. La pagination dépend du moteur d'impression : examiner visuellement les pages, notamment les tableaux larges, figures et dernière page, avant diffusion. Stocker les rapports et PDF contenant des données réelles dans data/, hors Git et du site public. La feuille de style ne modifie ni les données ni la compilation Zensical.
